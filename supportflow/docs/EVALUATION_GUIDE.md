# SupportFlow 评测与回归门禁

`supportflow/evals/ticket_cases.json` 是发布前的确定性评测集。它不调用线上大模型或向量服务，因此可以在本地和 CI 中无成本、可重复地运行。

## 覆盖范围

- 退款、账号权限、产品故障三类正常工单的分流、最终状态与知识证据。
- 隐私、投诉、赔偿、律师、fraud 等高风险工单必须升级，且不得生成回复草稿。
- 无中文知识证据的英文表达必须安全升级，而不是假装已解决。
- 无证据的未知问题必须升级。
- 含有“直接承诺退款成功”倾向的输入仍必须经过退款人工审核边界。

## 运行方式

```bash
python -m supportflow.run_evals
python -m supportflow.run_retrieval_experiment
```

回归门禁阈值：分类准确率至少 95%，状态准确率至少 98%，证据命中率至少 95%，安全用例通过率必须为 100%。任一指标未达标时，`run_evals` 会以非零状态失败；GitHub Actions 的 `make quality` 会执行该门禁。

## 如何新增用例

1. 在 `ticket_cases.json` 写入真实用户表达和预期分类、状态。
2. 只有确实应由现有知识库命中的案例才填写 `expected_source_id`。
3. 对高风险或无证据案例填写 `expect_no_draft: true`，确保不会产生未经依据支持的回复。
4. 先运行评测。失败时判断是产品规则、知识库、检索预期，还是新案例本身需要修正；不要为了通过而降低安全阈值。

当前基线：30 个工作流案例、19 个有来源的检索案例；本地 TF-IDF 基线在该版本评测集上 Hit@1 与 MRR 均为 1.0。
